# N5000 真机功能验收记录（2026-11-09）

环境：Intel N5000，ImmortalWRT SNAPSHOT `r0-5cd11f1`，内核 `6.18.55`，x86_64。
WAN：`eth3` 上的 PPPoE，MTU 1492，IPv4 `10.11.43.92`（CGNAT），
IPv6 `2408:824c:8002:386c:...`。
LAN：`br-lan` `10.10.10.1/24` + PD `2408:824c:8030:99b0::/60`；
NAS（验收客户端）`10.10.10.173`，`2408:824c:8030:99b0:...`。
honk（dae）在环，`/usr/share/honk/direct-unspec` 存在。

## 升级方式

原镜像只装了 ABI 15 的 `dpd-fastpath` + `einat-ebpf` + `honk` + router-*。
本轮用 `.apk` 在线升级（保留配置）：

`dpd-fastpath`、`dpdfwd`、`dpd-einat-sync`、`dpd-napi`、`dpd-observe`、
`dpd-honk`、`dpd-acl/qos/mwan`、`luci-app-dpd`。

验证：`dpdctl version/abi` = 20，`/usr/lib/dpd/abi` = 20；
升级后重启一次，`dpdfwd`/`dpd-observe`/`dpd-einat-sync` 都在运行。

## 验收中发现并修复的问题

1. **6.18.55 verifier**：新对象 L3 变体加载失败，
   `dereference of modified ctx ptr`（clang 把 ctx 指针 spill 后在
   `fib.ifindex = skb->ifindex` 处重载）。修复：在
   `dpd_fastpath_common()` 开头读一次 `skb->ifindex`，其余用标量局部；
   `dpd_nat_ext_addr()` 改为接收该标量。修复后 `classifier/l3` 在
   6.18.55 上加载并 jited（commit `ce424a6`）。
2. **`/etc/dpd` 不存在**：`dpdfwd` 默认读取 `/etc/dpd/class.conf`，但包没有
   创建目录，策略文件无法落盘。已给 `dpdfwd` 包加示例
   `files/class.conf`（conffile）和 `/etc/dpd` 安装目录。
3. **einat 模式下短流可能绕过策略**：学习路径要等 einat binding 镜像，
   极短连接可能在规则生效前完成。DPD NAT 模式下第一包就学习，策略立即
   生效（已实测）。这是设计边界，写入文档。
4. **升级触发 fw4 reload**：现场把 NAS 暴露到公网的规则是运行时 nft
   规则，reload 后丢失，导致管理入口中断；恢复为 UCI 规则后正常。运维上
   应把对外放行写成 UCI（见 `OPERATIONS.md`）。

## 已知/接受项

- **IPv6 重新获取慢**：用户确认不修（“慢点无所谓，正常就行”）。
  odhcpd 观测：有客户端 RS 时 ~16s 一次 RA；启动时先出现
  `No default route present, setting ra_lifetime to 0`，属 OpenWrt/PPPoE
  启动顺序，不是 DPD 引入。当前 NAS 已正常拿到新前缀地址。
- 性能门禁按决策取消（不做 64B/10G）。
- `bpf_ct_*`、NAT66、ICMP 错误报文未做（v1 范围外）。

## 结论

**v1 功能闭环通过**（N1–N10 的必须项 PASS）。升级后的 ABI 20 数据面在
N5000 + 6.18.55 + PPPoE + honk 在环的真实环境中可用；发现的两个代码/打包
问题已修复。剩余为环境不具备项（多 WAN、EIF 双 peer、VLAN）和明确接受项
（IPv6 慢、性能门禁）。
